# Порт Zak McKracken (SCUMM v2) для компьютера Электроника БК-0011М

**Zak McKracken and the Alien Mindbenders** (Lucasfilm Games, 1988) — квест «укажи и
щёлкни» на движке SCUMM: репортёр жёлтой газеты Зак Маккракен и три спутницы спасают
Землю от каппонианцев, которые оглупляют людей через телефонную сеть. Это перевод на Си
интерпретатора SCUMM v2 (по ScummVM) для улучшенной версии игры (Zak McKracken Enhanced
для DOS, графика EGA). Основа — порт Maniac Mansion для БК-0011М (maniac-bk0010): тот
же формат данных и та же машина.

## Что нужно

- **БК-0011М** (4 МГц) с контроллером **СМК-512** под ANDOS. СМК работает в режиме All:
  на настоящей машине нужна доработка **Б6** (ПЗУ БОС отключается сигналом с разъёма МПИ).
- Музыкальный сопроцессор **AY-3-8910** на порту 0177714 (как у «Мультизвука», такт 1,71 МГц).
- Мышь «Марсианка» (УВК-01) или джойстик на параллельном порту — по желанию.

На БК-0010 игра не запускается (сообщение NEED BK-0011M), без СМК — тоже (NEED SMK-512).
Электронный диск E: ANDOS игра портит: она берёт свободные страницы ОЗУ 11М под звук и
буфер загрузки.

## Что даёт БК-0011М

- **Звук на AY**: партии PCjr/Tandy оригинала — три голоса и шум (или, пунктом меню, поток
  PC-спикера на одном канале). Плеер Player_V2 работает в кадровом прерывании, в отдельной
  странице ОЗУ 11М.
- **Палитры**: у каждой комнаты своя из 16 палитр БК-0011М (tools/pal11.py подбирает её и
  узоры 2x2 для 16 цветов EGA); палитра меняется вместе с кадром.
- **Две экранные страницы**: прокрутка и смена комнаты рисуются в скрытой странице и
  показываются целиком; при чтении файлов экран не портится.
- **Кадровое прерывание**: время игры — точно 60 Гц, курсор от джойстика и мыши — в каждом
  кадре (~49 Гц).

## Управление

| Клавиша | Действие |
|---|---|
| ← → ↑ ↓ | курсор (пока клавиша нажата — повторяется) |
| ВВОД | щелчок: выбрать глагол, предмет, место |
| КТ | пропустить заставку (ESC); после конца игры — играть заново |
| СБР | меню: **1**, **2** — записать игру, **3**, **4** — загрузить, **7** — звук PCjr / PC-спикер |

Глаголы — буквенными клавишами по местам на экране (раскладка ЙЦУКЕН; ЛАТ/РУС и ЗАГЛ/СТР
не важны): **Й Ц У К Е / Ф Ы В А П / Я Ч С М И** (смена героя — глагол на месте **И**,
когда спутницы в игре). Инвентарь: **Ш**, **Щ** — верхние предметы, **Л**, **Д** —
нижние; **Г**, **О** — листать вверх и вниз.

Джойстик (раскладка «Стандарт»): ручка — курсор (с разгоном), A/X — щелчок, B/Y и Start —
пропуск заставки. Мышь «Марсианка»: перемещение — курсор, кнопки — щелчок и пропуск.

Записи хранятся в файлах ZKSAVE1, ZKSAVE2 на дискете. При неудаче в строке меню —
`ERROR к ддд` до нажатия клавиши: к = 1 — запись не помещается в файл, 2 — ошибка
записи, 3 — ошибка чтения, 4 — запись другой сборки игры (не загружается); ддд —
ответ драйвера дисковода в ПЗУ (восьмерично; 007 — прерывание по вектору 4 во время
обмена).

## Чем Zak отличается от Maniac Mansion

- **Данных больше** (914 Кбайт против 581): картинки комнат перекодированы при сборке
  оптимальным RLE того же формата (tools/lfl_patch.py: на 15–25% короче), у комнат 28 и 38
  картинка с маской вынесена в свой файл (псевдокомнаты 59 и 60), чтобы блок комнаты
  поместился в страницу СМК (24 Кбайт), а файл — в буфер загрузчика.
- **Куча ресурсов с вытеснением** (resource.c): глобальных скриптов, костюмов и звуков
  ~150 Кбайт; куча — до 4 страниц СМК, при нехватке освобождаются звуки, скрипты вне
  слотов и костюмы без актёров в комнате — они читаются из файла заново.
- **Логика Zak из ScummVM**: 13 актёров (объекты — с 14), до 33 объектов в комнате,
  `VAR_MACHINE_SPEED` = 0x7FFF (полная заставка EGA), `loadRoomWithEgo`, `endCutscene`,
  обход ошибки ScummVM #2285 (маскировка каппонианца); обходы для скриптов Maniac убраны.
- **Звук 95** (6038 байт) — слоты драйвера звука расширены.
- **Титры**: страница «Ported to BK 0011M by / Prcoder» после «Project Directed by»;
  в конце игры — «Press KT ...» вместо «Press ESCAPE ...».
- **Защита от копирования снята**: код визы в аэропорту (кнопки на экране) подходит любой
  (скрипт 15 в 52.LFL); код телефона и другие коды игры проверяются как в оригинале.

## Сборка и запуск

`make` собирает образ дискеты `bin/ZAK_<версия>.IMG` (ANDOS с автозапуском игры);
`make run` — в эмуляторе bk0010-emulator (БК-0011М, СМК-512, AY, дискета с записью).
Нужны:

- кросс-компилятор pdp11-aout (см. ниже) в `$(XGCC)` — по умолчанию `/home/prcoder/xgcc`,
  другой путь: `make XGCC=...`;
- python3 и gcc для хоста (сборка упаковщика tools/salvador);
- файлы игры 00.LFL..58.LFL (Zak McKracken Enhanced, DOS, английская версия; 00.LFL —
  md5 debe337f73d660e951ece7c1f1c81add) в каталоге проекта; исходные файлы сборка не
  меняет — правленые копии кладёт в bin/plfl;
- исходники ScummVM в /home/prcoder/scummvm (таблицы опкодов и шрифт; путь задан в Makefile);
- для `make run` — эмулятор в `$(EMU)` (по умолчанию
  `~/claude-experiments/bk0010-emulator/build/bk0010-emulator`).

На дискету файлы LFL идут сжатыми ZX0 (tools/salvador, tools/zx0lfl.py); распаковывает их
загрузчик (zx0.s). На дискете свободно ~16 кластеров по 2 Кбайт.

Для разработки:

| Команда | Что делает |
|---|---|
| `make shot` | прогон в эмуляторе без окна на `FRAMES` кадров (клавиши — `KEYS`), снимок в run.png |
| `make g-mpi` | образ — на Gryphon MPI по сети и запуск |
| `make sizes` | размеры ядра, общей копии, банков и драйвера звука |
| `make clean; make TIMING=1` | замеры частей шага игрового цикла |
| `make clean; make LIMB_C=1` | конечности актёров — моделью на Си вместо limb.s (сверка) |
| `rm resource.o; make HEAP_PAGES=1` | куча ресурсов в одну страницу — проверка вытеснения |
| `make -C test` | тесты на хосте (по правленым файлам bin/plfl): ресурсы, графика, полосы фона |

Ядро — в базовом ОЗУ, общая копия кода — во всех страницах СМК, банки кода A..D — в своих
страницах. Известные ошибки тулчейна и их обходы — в [TOOLCHAIN-BUGS.md](TOOLCHAIN-BUGS.md).

## Инструкция по сборке кросс-компилятора **gcc** для процессора **КР1801ВМ1** под ОС Linux

Для настройки кросс-компилятора gcc для процессора **КР1801ВМ1** понадобятся свежие исходники компилятора gcc,
которые можно взять с **ftp.gnu.org** из папки [gcc](https://ftp.gnu.org/gnu/gcc/) и свежие исходники *binutils*,
которые можно найти в папке [binutils](https://ftp.gnu.org/gnu/binutils/)

На момент написания это были версии **gcc-14.2.0** и **binutils-2.43**.

Сначала, создаём папку, в которую будем скачивать компилятор и *binutils* и заходим в эту папку:
```
mkdir -p gcc-KP1801BM1/src
cd gcc-KP1801BM1/src
```
Скачиваем в эту папку архивы с исходниками *gcc* и *binutils*, например так:
```
wget https://ftp.gnu.org/gnu/gcc/gcc-14.2.0/gcc-14.2.0.tar.gz
wget https://ftp.gnu.org/gnu/binutils/binutils-2.43.tar.gz
```

Распаковываем архивы с *gcc* и *binutils*:
```
tar -xvzf gcc-14.2.0.tar.gz
tar -xvzf binutils-2.43.tar.gz
```

Заходим в папку *gcc-14.2.0* и запускаем скрипт *./contrib/download_prerequisites*
```
cd gcc-14.2.0
./contrib/download_prerequisites
```

Применяем патч **gcc-KP1801BM1.patch** из папки проекта. Он добавляет ключ **-m1801vm1** — команды **sob и xor**, которые есть в процессоре **КР1801ВМ1**, но отсутствуют в **DEC PDP-11/10** (ставится после `-m10`: `-m10` его сбрасывает), — и исправляет ошибки gcc 14.2 для pdp11: bool из сравнений, сравнения и деление 32-битных чисел, потерю регистров при reload, побайтную запись в регистры устройств через битовые поля. Подробности — в [TOOLCHAIN-BUGS.md](TOOLCHAIN-BUGS.md):
```
patch -p1 < ~/БК0010-develop/zak-bk0010/gcc-KP1801BM1.patch
```

Затем заходим в папку *binutils-2.43* и так же применяем патч ассемблера **binutils-KP1801BM1.patch** из папки проекта: без него слишком дальний переход **br**/**bxx**/**sob** собирается без ошибки, но уходит не туда:
```
cd ../binutils-2.43
patch -p1 < ~/БК0010-develop/zak-bk0010/binutils-KP1801BM1.patch
```

Выходим снова в папку *gcc-KP1801BM1* и создаём там папку *build*, входим в неё и создаём папки для сборки компилятора и *binutils*:
```
cd ../..
mkdir build
cd build
mkdir gcc
mkdir binutils
```

Заходим в папку **binutils** и конфигурируем *binutils*:
```
cd binutils
../../src/binutils-2.43/configure --prefix $HOME/xgcc --bindir $HOME/bin --target pdp11-aout
```

В этой команде после параметра **--prefix** указан путь на папку с файлами кросс-компилятора, где будут находиться папки *include*, *lib* и т.д. кросскомпилятора.
В данном случае папка кросс компилятора будет расположена в домашней директории в папке *xgcc*.

После параметра **--bindir** указан путь куда будут помещены исполняемые файлы кросс-компилятора.
В данном случае использована папка *bin* в домашней папке пользователя.

Далее, собираем *binutils* и, затем, устанавливаем его по пути, указанном в предыдущей команде:
```
make -j7
make install
```

Параметр **-j7** после make указывает на то, что для сборки будут использованы семь ядер компьютера.
Имеет смысл указывать количество, на одно ядро меньшее, чем присутствует в компьютере - для избежания зависаний ОС во время сборки.

Далее, выходим из этой папки, и таким же образом конфигурируем *gcc* войдя в папку **gcc**:
```
cd ../gcc
../../src/gcc-14.2.0/configure --prefix $HOME/xgcc --bindir $HOME/bin --target pdp11-aout --enable-languages=c --with-gnu-as --with-gnu-ld --without-headers --disable-libssp
```

Затем, собираем *gcc* и устанавливаем его:
```
make -j7
make install
```

В результате этого процесса, после инсталляции, в папке **bin** *домашней папки* должны появится запускаемые файл компилятора, такие как **pdp11-aout-gcc**, **pdp11-aout-as**, а в папке **xgcc** (тоже в домашней папке) должны появится папки **include**, **lib**, **pdp11-aout** и др.

Файл **stdint.h** с 8-ми, 16-ти и 32-битными целыми типами лежит в папке проекта и подключается
ключом `-I.` раньше `$(XGCC)/include`, поэтому класть его в **xgcc/include** не нужно.
